When something gets settled, write the decision-log entry and update the
project state. Do not report that a log entry "is needed" or that it is "yours
to write" — Ray asked directly why he had to be involved in that.

**Why:** Recording the call is part of doing the work, not a separate approval
step. He has the log precisely so a future thread does not re-litigate; leaving
it unwritten defeats it and hands him clerical work.

**How to apply:** Both `nhsengineering` and `nhsrobotics` keep their own
`PROJECT.md`, `DECISIONS.md` and `REFERENCE.md` — never a shared set, because
`Class Development` holds three courses. Numbers are permanent; a reversal is
struck through with its reason and the entry that supersedes it, never deleted.
Note which repos an entry affects, since a decision can span both. Match the
existing voice: bold declarative claim, then the reasoning, then the date.
Never write a count you have not just verified. See [[terse-answers-only]] —
writing the log is not licence to narrate it in chat.
